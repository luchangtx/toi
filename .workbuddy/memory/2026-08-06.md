## 联机游戏「创建房间报错」修复（17:43）
- 现象：draw（你画我猜）/ gomoku（联机五子棋）点击创建房间报错。
- 根因排查：用 Node 模拟 `wx.connectSocket` 真连服务器，`createRoom()` 逻辑正常（建房/加入/双向 relay 全通过）→ 代码逻辑无 bug。报错是 WebSocket 连接本身失败，但原代码把失败笼统提示成「连接服务器失败」，看不到真实原因。
- 三种真实根因：① 未启动 server/ ② 开发者工具未勾「不校验合法域名」③ 真机调试用 `localhost` 指向手机自身而非电脑（最隐蔽）。
- 修复：
  - `utils/ws.js` 的 `connect()` 加 8s 连接超时 + 透传真实 `errMsg` 与当前 `url`；导出 `connectionHint(url)` 给出可操作排错建议（local 地址额外提示真机改用局域网IP）。
  - draw.js / gomoku.js 的错误处理器与 `.catch` 改用真实 `errMsg`，并在 SOCKET_ERROR/CONNECT_TIMEOUT 时附 `connectionHint`。
  - README 新增「创建房间报错排查」小节。
- 实测：成功路径建房 J8LU(seat0)/加入(seat1)/relay 正常；失败路径（server 未启动）明确 reject 并触发带 url 的错误事件。

## 联机方案改为微信云开发（18:40，用户确认）
- 用户反馈：没有后端服务、无法部署 ws 服务器。经确认改用**微信云开发实时同步**替代自建 WebSocket 中转（用户选「微信云开发同步」选项）。
- 改动：
  - `utils/ws.js`：`RoomClient` 传输层从 `wx.connectSocket` 改为云数据库 watch。房间状态存 `rooms` 集合（单文档 watch 监听成员变化），消息流存 `msgs` 集合（按 roomId 查询 watch）。所有写操作走 `room` 云函数（admin 权限）。对外接口 createRoom/joinRoom/send/on/destroy/isHost/room 完全不变 → 两游戏页仅改构造参数 `url: app.globalData.wsUrl` → `env: app.globalData.cloudEnv`。
  - 关键修复：云数据库 watch 会把**发送者自己的消息**也推送回来（原 ws 服务器只 relay 给他人）→ `_onMsgChange` 里过滤 `doc.from === self.id` 的自回声，否则五子棋/你画我猜会重复处理自己发的消息。
  - 新增 `cloudfunctions/room/{index.js,package.json}`：create/join/send/leave 四个 action，openid 取 `cloud.getWXContext().OPENID`，env 用 `DYNAMIC_CURRENT_ENV`。`project.config.json` 加 `cloudfunctionRoot: "cloudfunctions/"`。
  - `app.js`：加 `wx.cloud.init({env: globalData.cloudEnv, traceUser})`，`cloudEnv` 留空待用户填环境 ID。
  - 删除已废弃的 `server/` 目录（被云函数替代）。
  - README 全面改写：server/ws 章节 → 云开发配置章节（开通环境、填 cloudEnv、部署 room 云函数、建 rooms/msgs 集合并设权限、报错排查）。
- 校验：全部 JS/JSON 语法通过；用 mock（模拟 wx.cloud.callFunction + database.watch）跑客户端逻辑 11 项断言全通过（created/joined/peer-join/消息投递/自回声过滤/destroy）。
- 用户还需手动做：① 后台开通云开发拿 env id 填 app.js；② 上传 room 云函数并云端装依赖；③ 建 rooms/msgs 集合设「所有用户可读，仅创建者可读写」。
