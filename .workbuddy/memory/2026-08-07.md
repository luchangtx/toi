# 2026-08-07 工作日志

## 联机小游戏 bug 修复（你画我猜 / 联机五子棋）

### 现象
1. 你画我猜：输入房间号，页面看不到已输入的文字。
2. 你画我猜：访客加入后房主已进游戏，访客卡在「等待房管开始」界面。
3. 五子棋：双方能看到棋盘，但房主落子对方看不到。

### 根因定位
- Bug1：你画我猜的房间号输入框嵌在 `<scroll-view>` 内。WeChat 受控 `value` 输入框在 `scroll-view` 中配合 `bindinput` 的 `setData` 重渲染，部分基础库会出现输入不回显；五子棋输入框在普通 `view` 内正常（对照验证）。
- Bug2/3 同源：传输层 `utils/ws.js` 只用云数据库 `msgs` 集合的 `where().watch()` 监听业务消息，该 watch 在部分基础库/网络下不可靠，导致 `round`/`move` 等业务消息收不到（`rooms` 单文档 watch 正常，所以能互相发现、棋盘能显示）。

### 修改
- `pages/draw/draw.wxml`：net-menu 的 `<scroll-view>` 改为普通 `<view>`（与可用的五子棋输入框结构一致）。
- `utils/ws.js`：新增**增量轮询兜底**——客户端每 300ms 直接读 `msgs` 集合（`createdAt >= 上次游标-500ms` + `_id` 去重），保证消息必达；同时处理 watch 的 `init` 快照（加入前房主已发的 `round` 补发，避免卡等待屏）；`destroy()` 时已通过 `_stopWatch` 清理轮询定时器。
- `README.md`：强调 `msgs` 集合必须「所有用户可读」（轮询兜底需客户端读取）。

### 验证
- Node 模拟 `wx.cloud`（callFunction + database），故意让 watch 完全失效，仅靠轮询：房主建房、访客加入、房主发 `round`/`move`，访客均收到；自身回声过滤正确；轮询增量游标正常。7 项断言全 PASS。
- 4 个 JS 文件语法校验通过。

### 注意 / 待用户确认
- 轮询兜底依赖 `msgs` 集合「所有用户可读」权限，已写入 README；若用户仍卡等待屏，先查集合权限。
- 真机需填 `app.js` 的 `cloudEnv` 并部署 `room` 云函数（前一日已确认此方案）。

## 你画我猜：猜词方输入体验优化

### 现象
猜词方答案输入框位置太靠下（整页 scroll-view 把画布+画笔面板+聊天+玩家面板全堆在上面），需滚动到底才能输入，且输入框被挤压显示不全。

### 修改（pages/draw/）
- `draw.js`：data 新增 `isDrawer` 字段，在 `applyRole`(L477) 与 `afterRemoteRound`(L959) 同步设置（`isDrawerNow()` 在练习/本地模式已恒为 true，不会误伤本地双人）。
- `draw.wxml`：猜词方（`!isDrawer`）隐藏「画笔工具」「玩家」两块面板与正文内嵌输入框；新增底部 `guess-bar`（`wx:if="screen==='game' && !isDrawer"`）常驻屏幕底部输入条，画布保留（猜词需看对方作画）。绘制方完全保持原样。
- `draw.wxss`：新增 `.guess-bar`（position:fixed 底部、含 safe-area 适配）、`.guess-input`（flex:1; min-width:0 防挤压）、`.game-wrap.guess-mode`（padding-bottom 150rpx 防遮挡末尾退出按钮）。

### 要点
- `.guess-bar` 是 `.root` 直接子节点、与 scroll-view 同级，故 position:fixed 相对视口生效（规避 fixed 落在 scroll-view 内失效的坑）。
- `onSubmitGuess`/`onChatInput` 与 UI 无关，两种输入框复用同一逻辑。

## 你画我猜：猜词输入条被软键盘遮挡（二次修复）

### 现象
底部固定 `guess-bar` 仍「被挤压、显示不全」——根因是 `position:fixed; bottom:0` 未处理软键盘：键盘升起盖住视口底部，固定栏被压在键盘下。

### 修改（pages/draw/）
- `draw.js`：data 新增 `kbHeight`；新增 `onGuessFocus(e)`（取 `e.detail.height` 写入 kbHeight）、`onGuessBlur()`（归零）。
- `draw.wxml`：`guess-bar` 加 `style="bottom: {{kbHeight}}px;"`；guess-input 加 `adjust-position="{{false}}"`（关闭页面自动滚动，改由手动抬升）+ `bindfocus`/`bindblur`；`game-wrap` 加猜词态 class `{{!isDrawer ? 'guess-mode' : ''}}`（此前已定义 `.guess-mode` 的 150rpx 底部留白但从未挂载，现补上，避免退出按钮被固定栏挡住）。
- `draw.wxss`：`.guess-bar` 默认 `bottom:0` 作兜底，inline style 覆盖。

### 验证
- `node --check draw.js` 通过。键盘高度感知为 WeChat `<input>` 标准 `bindfocus` 字段，跨 iOS/Android 通用。

## 你画我猜：画画方输入框也被键盘遮挡（统一修复）

### 现象
用户在练习模式 / 本地双人模式（isDrawer 恒 true）实测，发现**画画一方**的「输入猜测框」同样被键盘遮挡。根因：此前仅底部 `guess-bar`（`wx:if="screen==='game' && !isDrawer"`）做了键盘避让，画画方用的是面板内嵌输入框（在 scroll-view 内），没有键盘处理，弹键盘即被压住。

### 修改（pages/draw/）
- `draw.wxml`：删除面板内嵌的 `chat-input-wrap`（画画方专属）；底部 `guess-bar` 条件改为 `screen==='game'`（画/猜双方共用），占位文案改通用「输入消息或猜测…」；`game-wrap` 始终挂 `guess-mode`（底部恒留 150rpx，避免固定条遮挡退出按钮）。
- `draw.wxss`：删除已无引用的 `.chat-input-wrap` / `.chat-input`（`.chat-ph` 仍被底部条复用，保留）。

### 结论
画/猜双方现共用同一条「键盘感知、固定底部」输入条，杜绝 scroll-view 内输入框被键盘遮挡的问题。逻辑 `onSubmitGuess`/`onChatInput` 不变。

## 输入框高度/文字竖向裁切（通用修复：微信 input 通病）

### 现象
- 你画我猜底部「输入消息或猜测」框：高度不够，placeholder 被竖向裁切（已修，height:88rpx; line-height:84rpx）。
- 两个联机游戏的「房间号」输入框也同类问题：draw 的 `.code-input`（net-menu 输入房号）、gomoku 的 `.room-id-input`。
### 根因
微信 `<input>` 只靠 `padding` 撑高、无显式 `height`/`line-height` 时，盒子高度小于文字行高，文字会被上下裁掉。
### 修复
- `draw.wxss` `.code-input`：`padding:24rpx` → `height:96rpx; line-height:92rpx; padding:0 24rpx`（border 2rpx，content=92=line-height）。
- `gomoku.wxss` `.room-id-input`：补 `box-sizing:border-box; height:88rpx; line-height:80rpx; padding:0 24rpx`（border 4rpx，content=80=line-height）。
### 经验
**微信 input 竖向裁切的统一解法**：显式 `height` + 相等 `line-height`（等于 content 高度 = height - 2×border），`box-sizing:border-box`，垂直 padding 改为 0。后续新建任何 `<input>` 都应直接套用，避免重复踩坑。
