# dsh · TOI 操作页面

在原版（`原版/timers.html`）**功能逻辑完全不变**的前提下，重新设计的一套操作界面。
新版把「业务逻辑」与「界面表现」彻底分层：核心脚本逐字沿用原版源码，新界面只做视觉与展示增强。

## 目录结构

```
dsh/
├── index.html                  # 新操作页面入口（直接双击打开即可）
├── statics/
│   ├── css/app.css             # 全新设计系统（深色 / 明亮双主题 + 响应式）
│   ├── img/iceHockey.png       # 图标（沿用原版）
│   └── js/
│       ├── timer_plus.js       # 原版业务逻辑，与原版源码逐字节一致
│       ├── console-ui.js       # 新增：纯展示层（G 高亮 / 计分牌 / 状态 / 人数 / 主题切换）
│       └── xlsx.full.min.js    # 导出 xlsx（沿用原版）
└── tests/
    ├── parity.mjs              # 差分测试：原版 vs 新版，逐步比对业务状态
    ├── screenshot.mjs          # 自动截图（桌面 / 移动端 / 各状态）
    └── screenshots/            # 截图产物
```

打开方式：双击 `dsh/index.html`（`file://` 已验证可用），或用任意静态服务器托管后访问。

## 功能对照（全部保留）

| 功能 | 交互 | 说明 |
| --- | --- | --- |
| 比赛设置 | 启动弹窗 | 队员人数 1–30、时长 1–20 分钟、主/客队；回车提交、水印显示队别 |
| 上场/下场 | 点击卡片 | 卡片高亮 + 顶部「在场」角标 |
| 开始 / 暂停 | 按钮、双击空格 | 空格需 0.5 秒内双击 |
| 快退 / 快进 | 按钮长按、← → | 按住 200ms 连发，仅比赛进行中可用 |
| 得分 / 失分 | 按钮、+ / - | 1 秒内连点去抖；写入进球记录与比分 |
| 全换 | 按钮 | 换下除 `G` 外的全部在场队员 |
| 编辑 | 卡片编辑按钮 / 编辑按钮 | 单人编辑与批量编辑号码、位置 |
| 查看 | 按钮 | 生成出场时间表 + 自动复制时长到剪贴板 |
| 重置 | 按钮 | 二次确认后清空时长、取消上场、保留号码与位置 |
| 导出 | 按钮 | 导出 `出场记录+时间戳.xlsx` |
| 终场 | 自动 | 倒计时归零提示「比赛结束」并自动打开出场时间表 |
| 其他 | 保留 | 重复号码校验、离场拦截、水印、禁用返回/刷新 |
| 明暗模式 | 顶栏右上角按钮 | 深色 ⇄ 明亮，选择写入 `localStorage`，刷新后保持 |

## 界面图标

全部按钮图标均为内联 SVG（描边/填充跟随文字颜色），不使用任何 emoji：

- 操作台 11 个按钮：快退、快进、开始、暂停、得分、失分、全换、编辑、查看、导出、重置；
- 顶栏主题切换按钮：太阳 / 月亮；
- 卡片右上角编辑按钮与弹窗关闭按钮：原脚本生成的是 `✏` 与 `×` 字符（脚本逐字节保留、不可改），
  这里用 CSS `mask` 遮罩图标覆盖，并把字号置零，因此渲染结果同样是矢量图标。

## 明亮模式

顶栏右上角的按钮可在**深色**（默认）与**明亮**之间切换，选择保存在 `localStorage`（键名 `toi-theme`），
刷新不丢失；`<head>` 内的内联脚本会在样式生效前恢复主题，避免闪屏。

明亮模式只覆盖配色（背景 / 边框 / 文字 / 阴影 / 图标色），不含任何尺寸与布局声明，
因此响应式与交互行为完全一致；G 的金色区分在两种主题下都保留（明亮模式改用更深的琥珀金以保证对比度）。

## 位置 G（守门员）颜色区分

只要位置填 `G`（大小写均可，脚本统一转大写），该队员在三个位置同时以**金色**区分，普通队员保持冰蓝/玻璃色：

1. **球员卡片**：金色边框 + 左侧金色标记 + 金色号码 + 底部「守门员」角标；
2. **位置徽标**：徽标底色转为琥珀金（原逻辑即有此行为，新版沿用主题色）；
3. **出场时间表 / 批量编辑**：`G` 所在行整行金色高亮（排序仍保持守门员置顶）。

在场状态与守门员状态可叠加：`G` 队员在场时为「金框 + 冰蓝在场角标」。

## 验证

```bash
node dsh/tests/parity.mjs      # 逻辑一致性差分测试（虚拟时钟，逐步比对）
node dsh/tests/screenshot.mjs  # 生成界面截图
```

`parity.mjs` 的做法：用无头 Chrome 同时打开原版与新版，注入虚拟时钟（替换 `setInterval/setTimeout/Date`），
执行同一串 30 步操作（设置、编辑、上场、开始、快进快退、得分失分去抖、全换、查看、导出、重置、
重复号码校验、终场、空格切换、长按连发、弹窗关闭等），每一步采集同一份业务状态快照并逐字段比对。

最近一次结果：**30/30 步业务状态完全一致**；新界面专属校验 **17/17 通过**
（G 颜色区分、HUD、DOM 钩子、明亮模式切换与持久化、明亮模式下的 G 对比度、矢量图标与字号归零）；
两页在整个流程中**页面运行期异常均为 0 条**（含未捕获异常与 `console.error`）。

另外已验证：直接双击 `dsh/index.html` 以 `file://` 打开时，样式、脚本、卡片生成、G 高亮、
xlsx 导出依赖均正常，无控制台异常。

## 与原版的差异（仅界面层）

- 布局：顶部计分牌 + 阵容网格 + 吸底操作台 + 结果区，全响应式，深色 / 明亮双主题；
- 新增只读 HUD：本方队伍、人数、时长、在场人数、比分、待开始/进行中/已暂停、最后 1 分钟与终场提醒；
- 卡片、弹窗、表格、提示条、水印全部重绘；交互与状态机完全沿用原脚本；
- 原脚本依赖的类名与 ID（`.container/.card/.selected/.number/.role/.timer/.score/.edit-button/...`）全部保留，
  因此 `timer_plus.js` 可原样升级替换。

移动端（414×896）实测：顶栏 + 操作台占视口 **44%**（原设计初版为 64%），其余为阵容可视区；
批量编辑弹窗的关闭按钮改为吸顶，30 人列表滚动到底仍可关闭。

### 继承自原版、未作改动的行为

以下都是原脚本的既有逻辑，为保证「功能逻辑不变」而刻意保留，不是本次改版的缺陷：

- 「重置」只清空各队员上场时长与在场状态，进球记录与计分牌保留（原脚本即如此，确认文案仍为原文）；
- 卡片编辑按钮默认悬停显示、卡片不支持键盘聚焦（原版相同）；
- 离开页面仍会弹出「确定要离开此页面吗？」并禁用浏览器返回。
